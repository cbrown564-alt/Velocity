# Native PowerPoint research-visualisation system

## Decision

Velocity's E6 target is a professional market-research PowerPoint system, not publication graphics recreated from freeform shapes.

**Hard invariant:** every quantitative data mark in the final report must belong to a native Office chart object with inspectable/editable embedded workbook data. PowerPoint shapes/text may frame, annotate and explain charts, but must not substitute for quantitative marks.

This deliberately accepts some visual constraints in exchange for the defining handover property of professional market-research decks: a researcher can right-click a chart, choose Edit Data, inspect the numbers, change them and retain a coherent visual.

## Architecture

The system has four layers.

### 1. Theme

- 16:9 canvas;
- editorial headline + neutral sans-serif body;
- warm neutral page field;
- restrained semantic palette;
- chart palette where most series are neutral and one analytical subject may receive accent;
- red reserved for deterioration/risk, amber for partial recovery/caution;
- accessible distinction must not depend on colour alone.

### 2. Slide layouts

Reusable compositions, independent of chart family:

1. cover;
2. executive synthesis;
3. full-width hero chart;
4. chart + commentary;
5. two-chart juxtaposition;
6. small multiples (2–4 independent native charts with synchronised configuration);
7. chart + evidence strip;
8. section opener;
9. closing questions.

The chart normally receives 65–80% of the useful analytical canvas. Typography and interpretation live outside the chart object.

### 3. Native research-chart primitives

The first library:

- `MR_BAR_RANKED`
- `MR_BAR_COMPARE`
- `MR_STACKED_100`
- `MR_LIKERT_DIVERGING`
- `MR_BAR_DIVERGING_NET`
- `MR_TREND_HERO`
- `MR_TREND_COMPARE`
- `MR_SLOPE_TWO_PERIOD`
- `MR_DUMBBELL_XY`
- `MR_DUMBBELL_XY_MULTI`
- `MR_SCATTER_POSITION_CHANGE`
- `MR_SCATTER_QUADRANT`
- `MR_INDEX_VS_BENCHMARK`
- `MR_NPS_COMPOSITION`

Each primitive has a semantic data contract and an Office implementation recipe. The generator selects the semantic primitive, not merely a raw chart type.

### 4. Editorial layer

The story/visual-argument layer decides:

- finding-led headline;
- explanatory dek;
- highlighted series/category;
- contextual series to mute;
- reference marks;
- annotation target;
- displayed values;
- methodological qualification;
- base/question/source notes;
- omission.

This is where publication-style hierarchy is achieved while the chart itself remains native and inspectable.

## Native-chart invariant

For any quantitative visual:

1. all plotted positions/lengths/areas are generated by an Office chart series;
2. embedded workbook contains human-readable display data;
3. advanced primitives may use helper data, but helper columns are separated/documented and never replace the clean display table;
4. a researcher can edit display values and understand their relationship to the graphic;
5. freeform PowerPoint shapes may not encode a numeric value;
6. chart annotations may be shapes/text only when they describe/contextualise a native mark rather than replacing it.

Text-only slides and non-quantitative editorial signposts are exempt.

## Workbook convention

Advanced charts use two logical sections:

### DISPLAY DATA

The clean research table a human expects, for example:

| Segment | W2 | W3 | Change |
|---|---:|---:|---:|
| 18–34 | 26.0 | 37.1 | +11.1 |
| 35+ | 18.1 | 23.3 | +5.3 |

### HELPER DATA

Generated coordinates/transforms required by Office chart mechanics, e.g. Y positions, neutral splits, error-bar lengths or label coordinates.

Helper data must be deterministic from display data and documented by the primitive.

## Research metadata

Every primitive supports a common metadata envelope:

- question wording / question ID;
- universe/base definition;
- unweighted base(s);
- weighting;
- period/wave;
- significance notation and comparison rule;
- low-base/suppression state;
- source.

The slide renderer decides which metadata is displayed locally, but the report contract preserves it.

## Chart defaults

- chart title inside chart object: off;
- chart border/background: off/transparent;
- legend: off when direct labels are practical;
- direct labels: preferred;
- gridlines: minimal and subordinate;
- axes: only where they improve quantitative reading;
- bars: zero baseline unless a specialised diverging primitive;
- line/scatter: explicit, defensible scale; never use a cropped range to manufacture drama;
- no 3D;
- no smoothing for tracker series;
- no rainbow categorical palette by default;
- no unexplained bubble size;
- percentage, percentage-point and NPS-point units remain distinct;
- displayed deltas are computed from unrounded source estimates then rounded consistently.

## SBT-001 integration requirement

Rebuild the Category Board through this system:

- Slide 2: native microcharts/evidence charts where quantitative marks are shown;
- Slide 3: `MR_SCATTER_POSITION_CHANGE`;
- Slide 4: `MR_TREND_HERO`;
- Slide 5: `MR_DUMBBELL_XY`;
- Slide 6: `MR_DUMBBELL_XY_MULTI`;
- Slide 7: separate native customer and market charts arranged as a juxtaposition;
- Slide 8: native recovery/reference charts;
- Slide 9: `MR_TREND_COMPARE`;
- Slides 1/10: text-led, with no requirement to manufacture charts.

No data-bearing SBT-001 slide passes E6 if its quantitative marks are freeform shapes.

## Acceptance

The milestone is complete when:

1. primitive registry/data contracts are committed;
2. reusable native-chart builder exists for the core primitive families;
3. advanced XY dumbbell and diverging-Likert recipes are implemented/documented;
4. automated PPTX inspection verifies data-bearing slides contain native chart objects and embedded workbook relationships;
5. SBT-001 Category Board is generated solely through the native chart system;
6. Edit Data inspection is documented for every quantitative slide;
7. rendered full-size and contact-sheet QA pass;
8. E6 grading contract explicitly treats non-native quantitative marks as a hard failure.
