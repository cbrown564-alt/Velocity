Global invariants

01

No React in core/engine. Pure TypeScript only — portable to Node, workers, and future runtimes.

02

Worker-side compute. DuckDB queries never block the main thread (>16ms forbidden).

03

Dual-state integrity. Integer codes in SQL; display labels in UI. Never conflate.

04

ResultEnvelope provenance. Every engine op returns inputs, duration, warnings, metadata.

05

Thin transports. MCP handlers and worker routers delegate — no business logic.

06

Session stability. .velocity format is versioned; no field removals without migration.

Survey-native significance

arch_04 · pilot_02

❌ Cell vs total (generic BI)

Compares subgroup to the column total — biased when the total contains the subgroup being tested.

✓ Cell vs rest (Velocity)

Compares each cell to all other respondents in that column. Welch's t-test with Kish ESS for weights.

src/core/analysis/crosstab/significance.tsL19–23
const DEFAULT_SIGNIFICANCE_OPTIONS = {
  comparisonMethod: 'cell_vs_rest',
  correctionType: 'none',
  significanceLevel: 0.95,
};

ResultEnvelope — provenance by default

engine/types.ts

Every engine operation wraps its result with inputs, duration, warnings, and metadata. Mandatory for defensible survey research and agent auditability.

src/engine/types.ts
export interface ResultEnvelope<T> {
  data: T;
  operation: string;
  inputs: Record<string, unknown>;
  durationMs: number;
  warnings: string[];
  metadata: {
    datasetName: string;
    rowCount: number;
    filtersApplied: number;
    isWeighted: boolean;
    engineVersion: string;
  };
}

Get started

Local setup, verification gates, and the docs to read before your first PR.

Clone & install

Node.js v20+, npm workspaces. Submodule required for readstat-wasm.

git clone <repo> && cd velocity
git submodule update --init --recursive
npm ci --legacy-peer-deps

Start dev server

COOP/COEP headers enabled for DuckDB-Wasm multi-threading.

npm run dev
